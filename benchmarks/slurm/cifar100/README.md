# CIFAR-100 jobs

Six models — `cnn_gn_cifar100`, `vit_micro_cifar100`, `resnet20_cifar100`, `cct_2_3x2_cifar100`,
`resnet50_cifar100`, `vit_small_cifar100` — x (1 calibration + 1 grouped + 7 per-arm) = 54 scripts,
all generated by `../generate_jobs.py`. Results land in `benchmarks/outputs/cifar100/<model>/`.

## What is and is not new here

Nothing about the protocol is. CIFAR-100 is the same 50 000 32x32x3 images as CIFAR-10 under the
same seeded 45k/5k split (`common/data.py`), the same "pad 4, random 32x32 crop from the image or
its horizontal flip" of `resnet_1512.03385.pdf` §4.2, the same Cutout, and the same 7 arms under
the same wall-clock-time protocol. Each model is its CIFAR-10 counterpart with a 100-way head —
`resnet20_cifar100` has 275 572 parameters against `resnet20_cifar`'s 269 722, and the hooked-module
inventory is identical, which `tests/test_benchmark_models.py` asserts model by model.

Two consequences worth stating plainly:

* **The `--time` values are DERIVED, not measured.** Each is its CIFAR-10 counterpart's measured
  figure, unchanged, because the compute differs by the head alone (+2% of parameters at worst).
  That is a defensible transfer, not a measurement. The calibration job still exists for each
  model and is still worth running once.
* **The hyperparameters are the CIFAR-10 ones, not re-tuned.** AdaFisher's Table 9 / Appendix D
  operating point (`lr=1e-3`, `Lambda=1e-3` or `3e-3`, decay `5e-4` for CNNs and `1e-2` decoupled
  for ViTs) is what every arm uses, exactly as on CIFAR-10. A 100-class problem at the same
  learning rate is a harder problem, not a differently-tuned one; read the accuracies accordingly.

## Running them

```bash
# calibration first (2 epochs x 7 arms on a 5k subset): turns a DERIVED --time into a measured one
sbatch benchmarks/slurm/cifar100/calibrate_resnet20_cifar100.sh

# then the whole model in one job — the reference arm defines the budget in-process, so there is
# no --wct-budget to copy by hand (which is what produced mislabelled checkpoints in campaign 1)
sbatch benchmarks/slurm/cifar100/train_resnet20_cifar100_all.sh
```

The per-arm scripts exist for when the seven arms should run concurrently; then the `diag` job
must finish first and its measured `total_s` be passed to the other six:

```bash
sbatch benchmarks/slurm/cifar100/train_resnet20_cifar100_diag.sh
B=$(python -c "import json;print(json.load(open('benchmarks/outputs/cifar100/resnet20_cifar100/diag/manifest.json'))['arms']['diag']['total_s'])")
for a in kfac ekfac tkfac tekfac adam adamw; do
  sbatch --export=ALL,WCT_BUDGET="$B" benchmarks/slurm/cifar100/train_resnet20_cifar100_$a.sh
done
```

Prerequisite: `dataset/cifar-100-python/` must be staged next to `dataset/cifar-10-batches-py/`
(see `../README.md` step 3). `--no-allow-download` makes a missing dataset a clear error rather
than a network timeout on a node with no internet.
