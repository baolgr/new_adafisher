# SLURM jobs — lot 8, CIFAR-10 / ResNet-50 / ViT-S/4, seven optimizer arms

16 scripts: 2 calibration jobs + 14 training jobs (`{resnet50, vit_small} × {diag, kfac, ekfac,
tkfac, tekfac, adam, adamw}`), all generated by `generate_jobs.py` — **edit that file, never the
`.sh` files**. Design rationale for every choice below: `docs/reports/plan_lot8.md`, §0.7 (the WCT
budget protocol), §0.11 (why the cluster at all) and §1.5.

**Cluster.** The Alliance Canada H100 clusters (Fir or Rorqual) that
`/Users/baolgr/Documents/AtlasAnalyticsLab` already runs on. Every cluster-specific line in these
scripts is copied from job scripts that have actually run there, not re-derived — that repository's
`experiments/default/slurm/README.md` documents each one against `docs.alliancecan.ca` and against
live `module spider` output, and is the file to read first if this is your first submission.

## Before your first submission

1. **Get the repository onto the cluster** (`git push`/`clone`, or `rsync -av --exclude-from=.gitignore .`).
2. **Stage CIFAR-10 into `dataset/`** — required. Rorqual's compute nodes have **no internet**, and
   every script passes `--no-allow-download` so a missing dataset fails immediately with a clear
   error instead of hanging on a network timeout:
   ```bash
   # locally, once: populate ./dataset/cifar-10-batches-py/
   python -c "from torchvision.datasets import CIFAR10; CIFAR10('dataset', train=True, download=True); CIFAR10('dataset', train=False, download=True)"
   rsync -av dataset/ your-cluster:~/path/to/adafisher/dataset/
   ```
   Use the login/copy node for `rsync`, not a Globus-only endpoint.
3. `benchmarks/slurm/logs/` must already exist (`--output` writes there) — it is kept in the
   repository by `logs/.gitkeep`.
4. Nothing else: each job builds its own `$SLURM_TMPDIR` virtualenv from `requirements-cluster.txt`
   and sets `PYTHONPATH=$SLURM_SUBMIT_DIR/src`. The package is deliberately not installed (see that
   file's header).

## Submission order

**1. Calibrate first (2 jobs, ~45 min + ~30 min).**

```bash
sbatch benchmarks/slurm/calibrate_resnet50.sh
sbatch benchmarks/slurm/calibrate_vit_small.sh
```

2 epochs of every arm on a 5 000-image training subset. What to read off its `summary.md` and its
log, before spending real cluster time:

- **median step time and steps/s per arm** → turns each training script's `--time` from an
  extrapolation into a measurement (see "What the scripts request" below);
- **peak memory** → confirms `plan_lot8.md` §0.4's `fisher_batch_samples=32` (ResNet-50) and §0.5's
  mandatory `conv_sua=True` keep `ekfac`/`tekfac` inside the 10 GB MIG slice. If they do not, lower
  `--fisher-batch-samples` (16, 8) rather than dropping an arm; if there is headroom to spare, raise
  it — the knob changes the curvature *estimator*, so it is reported in the summary and must not be
  changed silently between arms.

**2. The two reference arms (2 jobs).** Their measured wall-clock time is every other arm's budget
(`plan_lot8.md` §0.7 — AdaFisher's own WCT protocol, `adafisher_2405.16397.pdf` §5).

```bash
sbatch benchmarks/slurm/train_resnet50_diag.sh
sbatch benchmarks/slurm/train_vit_small_diag.sh
```

Read the budget back once they finish:

```bash
python -c "import json;print(json.load(open('benchmarks/outputs/lot8_cifar10/resnet50/diag/manifest.json'))['arms']['diag']['total_s'])"
```

**3. The remaining 12 arms**, each with that number:

```bash
for arm in kfac ekfac tkfac tekfac adam adamw; do
  sbatch --export=ALL,WCT_BUDGET=<resnet50 diag total_s> benchmarks/slurm/train_resnet50_$arm.sh
  sbatch --export=ALL,WCT_BUDGET=<vit_small diag total_s> benchmarks/slurm/train_vit_small_$arm.sh
done
```

All 12 are independent and can run concurrently. **Without `WCT_BUDGET` a job still runs**, falling
back to `--budget-mode epochs` — the equal-epoch comparison `plan.md` §6.3 explicitly calls rigged
in favour of the expensive modes. Usable as a cross-check, not as this lot's headline result.

**4. Aggregate.** Each arm writes its own `benchmarks/outputs/lot8_cifar10/<model>/<arm>/`
(`records.csv`, `epochs.csv`, `summary.md`, `manifest.json`, 4 plots). Re-running the entrypoint
locally with `--arms` listing several arms produces one combined report; across independent jobs,
concatenate the per-arm CSVs.

Track jobs with `sq`; do **not** poll it in a tight loop — the Alliance docs warn this degrades the
scheduler for everyone.

## What the scripts request, and why

- **`--gpus=h100_1g.10gb:1`** — a MIG slice (1/8 compute, 10 GB), not a full H100: `def-msh-ab`'s
  GPU allocation on Rorqual supports only that shape (confirmed there via `sshare -U` and a real
  validation run). `--gres=gpu:` is deprecated in favour of `--gpus`/`--gpus-per-node`. On an
  account with a full-GPU allocation, `--gpus=h100:1` (or `h100_3g.40gb:1`) is the one-line switch —
  and would let you drop `--fisher-batch-samples` and re-run the ResNet-50 arms without SUA.
- **`--mem=16G`** — CPU-side memory. `--mem=0` (all node memory) is actively harmful on a shared MIG
  node. The GPU-side budget is the 10 GB of the slice, which is what the calibration job measures.
- **`--cpus-per-task=8`**, matching `--num-workers 8` in each script, and under both clusters'
  documented per-GPU maximum (Fir 12, Rorqual 16). Raise both together if `sacct -j <id>
  --format=Elapsed,MaxRSS` suggests the job is data-loading bound.
- **`--time=04:00:00` (ResNet-50) / `01:30:00` (ViT-S/4)** — **unmeasured extrapolations**, flagged
  as such in every script's header. Basis: real `sacct` numbers for the same two models, the same
  batch size 128 and the same 45k CIFAR-10 split, on this cluster, from
  `AtlasAnalyticsLab/experiments/*/slurm/README.md` — ~85 min for 40 ResNet-50 epochs (≈2.1
  min/epoch → ≈1h45 for 50) and 20-22 min for 40 ViT-small epochs (≈0.55 min/epoch → ≈28 min for
  50), doubled for AdaFisher's per-step overhead and job setup. Under the WCT protocol every arm of
  a model takes ≈ the reference arm's wall-clock time, which is why all seven share one budget.
  Re-tighten after the calibration job, and again from real `sacct` data after the first training
  submission.
- **No `--partition`** — deliberate; the Alliance docs' own guidance is to let the scheduler place
  the job from the requested resources.
- **`module purge` before `module load`** — the docs' own troubleshooting guidance, so jobs are
  submitted from a uniform environment.
- **`set -euo pipefail` and `cd "$SLURM_SUBMIT_DIR"`** — every path inside the scripts is relative to
  the repository root, so submit from there.

## What one job actually runs

```bash
python benchmarks/cifar10_classification.py --model <model> --arms <arm> --epochs 50 \
  [--budget-mode wct --wct-budget <T> --max-epoch-factor 3 | --budget-mode epochs] \
  --num-workers 8 --no-allow-download --data-root "$SLURM_SUBMIT_DIR/dataset" \
  --output-dir "$SLURM_SUBMIT_DIR/benchmarks/outputs/lot8_cifar10/<model>/<arm>"
```

Everything else — learning rate, weight decay and its coupled/decoupled convention, damping,
`conv_sua`, `fisher_batch_samples` — is resolved per model from `MODEL_DEFAULTS` in that script,
which carries AdaFisher's own tuned values with their citations (`plan_lot8.md` §0.8). Override any
of them on the command line if you are running a variant; do not edit the defaults for one arm only.
