# SLURM jobs — one calibration job and seven optimizer arms per model

70 scripts: for each of the eight model folders under `benchmarks/`, one calibration job plus 7
per-arm training jobs (`diag, kfac, ekfac, tkfac, tekfac, adam, adamw`); plus, for the six small
models, one `train_<model>_all.sh` running all seven arms in a single job. All generated by
`generate_jobs.py` — **edit that file, never the `.sh` files**. It enumerates the model folders
themselves (`plan_exp_step1.md` §6), reading each `Benchmark`'s own epoch count, arm list and
dataset, so a new model folder brings its own jobs with no edit here. Design rationale for every
choice below: `docs/reports/plan_lot8.md`, §0.7 (the WCT budget protocol), §0.11 (why the cluster
at all) and §1.5.

**Every `--time` is now measured.** The calibration pass has run for all eight models; each
script's header quotes the worst arm's steady-state `median fwd+bwd + median step` on one
`h100_1g.10gb` slice, extrapolated to that model's own full split and epoch count. Re-run
`generate_jobs.py` after changing any model's epoch count or batch size.

**Cluster.** The Alliance Canada H100 clusters (Fir or Rorqual) that
`/Users/baolgr/Documents/AtlasAnalyticsLab` already runs on. Every cluster-specific line in these
scripts is copied from job scripts that have actually run there, not re-derived — that repository's
`experiments/default/slurm/README.md` documents each one against `docs.alliancecan.ca` and against
live `module spider` output, and is the file to read first if this is your first submission.

## Quickstart: from a pushed repo to running jobs

You've already pushed the repository to a remote reachable from the cluster (GitHub/GitLab, or a
bare repo of your own). This is what turns that push into running SLURM jobs, on a fresh account
that has never submitted here before.

1. **SSH into a login node** (Fir or Rorqual — pick the one your `def-msh-ab` allocation is on):

   ```bash
   ssh <username>@fir.alliancecan.ca      # or rorqual.alliancecan.ca
   ```

2. **Clone the repo onto the cluster's filesystem.** Pushing to a remote does not put files on the
   cluster by itself — clone from that same remote, into your project space (`~/projects/def-msh-ab/…`
   or `~/scratch/…`, not `$HOME`, which has a small quota):

   ```bash
   cd ~/projects/def-msh-ab/<username>
   git clone <your-remote-url> adafisher
   cd adafisher
   ```

   Already cloned from a previous attempt? `cd` into it and `git pull` instead.

3. **Stage CIFAR-10 into `dataset/`** — do this from your laptop, not the cluster: compute nodes on
   Rorqual have no internet, and the login node is not the place to run `torchvision`'s download.

   ```bash
   # locally, once: populate ./dataset/cifar-10-batches-py/
   python -c "from torchvision.datasets import CIFAR10; CIFAR10('dataset', train=True, download=True); CIFAR10('dataset', train=False, download=True)"
   rsync -av dataset/ <username>@fir.alliancecan.ca:~/projects/def-msh-ab/<username>/adafisher/dataset/
   ```

   Use the login node for `rsync` (or a dedicated data-transfer node if your cluster has one) —
   never a Globus-only endpoint.

4. **Confirm `benchmarks/slurm/logs/` exists** (it should — tracked via `logs/.gitkeep`):

   ```bash
   ls benchmarks/slurm/logs/
   ```

5. **Nothing to install by hand.** Each job builds its own `$SLURM_TMPDIR` virtualenv from
   `requirements-cluster.txt` and loads its modules (`StdEnv/2023 gcc/13.3 cuda/12.6 python/3.11.5`)
   at submission time — do not `pip install` anything on the login node.

6. **Submit, in the order below** ("Submission order"). Start with the calibration job of the
   model you want; do not fire all 64 scripts at once.

Everything from here on assumes you are in the repository root on the login node, submitting with
`sbatch benchmarks/slurm/<script>.sh`.

## Before your first submission

1. **Get the repository onto the cluster** (`git push`/`clone`, or `rsync -av --exclude-from=.gitignore .`).
2. **Stage CIFAR-10 into `dataset/`** — required. Rorqual's compute nodes have **no internet**, and
   every script passes `--no-allow-download` so a missing dataset fails immediately with a clear
   error instead of hanging on a network timeout:
   ```bash
   # locally, once: populate ./dataset/cifar-10-batches-py/
   python -c "from torchvision.datasets import CIFAR10; CIFAR10('dataset', train=True, download=True); CIFAR10('dataset', train=False, download=True)"
   rsync -av dataset/ your-cluster:~/path/to/adafisher/dataset/
   ```
   Use the login/copy node for `rsync`, not a Globus-only endpoint.
3. `benchmarks/slurm/logs/` must already exist (`--output` writes there) — it is kept in the
   repository by `logs/.gitkeep`.
4. Nothing else: each job builds its own `$SLURM_TMPDIR` virtualenv from `requirements-cluster.txt`
   and sets `PYTHONPATH=$SLURM_SUBMIT_DIR/src`. The package is deliberately not installed (see that
   file's header).

## Which submission strategy

Two ways to run one model's seven arms; the trade is parallelism against setup cost.

| | jobs per model | when |
|---|---|---|
| `train_<model>_all.sh` | **1** | the six small models — `mnist_autoencoder`, `mlp_ln_mnist`, `cnn_gn_cifar`, `vit_micro_cifar`, `cct_2_3x2_cifar`, `resnet20_cifar` |
| `train_<model>_<arm>.sh` + dispatcher | 7 (+1) | `resnet50_cifar`, `vit_small_cifar` |

Every job pays module load + `virtualenv` + `pip install --no-index` + dataset load, and on the
six small models that setup costs more than the training: 42 per-arm jobs are ~1.3 h of compute
against ~7 h of setup. One grouped job per model turns that into ~1 h of setup, and the runner
does the whole WCT protocol in-process — reference arm unbudgeted, its measured time as every
other arm's budget, one combined report — so there is no `WCT_BUDGET` to pass and no dependency
to chain.

The two large models stay split. Their setup is a quarter of the total, serialising ResNet-50's
seven arms would be a ~6.5 h job (which backfills far worse than seven 47-minute ones), and a
grouped job loses every completed arm if a later one crashes, since `main` writes its report only
at the end.

Whole campaign, both strategies combined: **21 jobs, ~12 h of MIG-slice time** — against 57 jobs
and ~18 h if every arm gets its own job.

```bash
# the six small models, one job each — nothing to chain
for m in mnist_autoencoder mlp_ln_mnist cnn_gn_cifar vit_micro_cifar \
         cct_2_3x2_cifar resnet20_cifar; do
  sbatch benchmarks/slurm/train_${m}_all.sh
done

# the two large models, per arm, via the dispatcher
MODELS="resnet50_cifar vit_small_cifar"
DEPS=""
for m in $MODELS; do
  jid=$(sbatch --parsable benchmarks/slurm/train_${m}_diag.sh); DEPS="$DEPS:$jid"
done
sbatch --dependency=afterok${DEPS} --export=ALL,MODELS="$MODELS" \
       benchmarks/slurm/dispatch_remaining_arms.sh
```

The per-arm steps below apply to the split strategy.

**1. Calibrate first (2 jobs, ~45 min + ~30 min).**

```bash
sbatch benchmarks/slurm/calibrate_resnet50_cifar.sh
sbatch benchmarks/slurm/calibrate_vit_small_cifar.sh
```

2 epochs of every arm on a 5 000-example training subset. What to read off its `summary.md` and its
log, before spending real cluster time:

- **median step time and steps/s per arm** → turns each training script's `--time` from an
  extrapolation into a measurement (see "What the scripts request" below);
- **peak VRAM** → the `peak VRAM` column of `summary.md` (`torch.cuda.max_memory_allocated`,
  reset per arm, covering training *and* evaluation) confirms `plan_lot8.md` §0.4's
  `fisher_batch_samples=32` (ResNet-50) and §0.5's mandatory `conv_sua=True` keep `ekfac`/`tekfac`
  inside the 10 GB MIG slice. It is *allocator* memory: the CUDA context and cuDNN workspaces sit
  on top, so it under-reports `nvidia-smi` by roughly 0.5-1 GB. If they do not, lower
  `--fisher-batch-samples` (16, 8) rather than dropping an arm; if there is headroom to spare, raise
  it — the knob changes the curvature *estimator*, so it is reported in the summary and must not be
  changed silently between arms.

**2. The two reference arms (2 jobs).** Their measured wall-clock time is every other arm's budget
(`plan_lot8.md` §0.7 — AdaFisher's own WCT protocol, `adafisher_2405.16397.pdf` §5).

```bash
sbatch benchmarks/slurm/train_resnet50_cifar_diag.sh
sbatch benchmarks/slurm/train_vit_small_cifar_diag.sh
```

Read the budget back once they finish:

```bash
python -c "import json;print(json.load(open('benchmarks/outputs/resnet50_cifar/diag/manifest.json'))['arms']['diag']['total_s'])"
```

**3. The remaining 6 arms per model**, each with that number:

```bash
for arm in kfac ekfac tkfac tekfac adam adamw; do
  sbatch --export=ALL,WCT_BUDGET=<resnet50_cifar diag total_s> benchmarks/slurm/train_resnet50_cifar_$arm.sh
  sbatch --export=ALL,WCT_BUDGET=<vit_small_cifar diag total_s> benchmarks/slurm/train_vit_small_cifar_$arm.sh
done
```

All 12 are independent and can run concurrently. **Without `WCT_BUDGET` a job still runs**, falling
back to `--budget-mode epochs` — the equal-epoch comparison `plan.md` §6.3 explicitly calls rigged
in favour of the expensive modes. Usable as a cross-check, not as this lot's headline result.

**Unattended alternative.** `dispatch_remaining_arms.sh` (hand-maintained, not generated by
`generate_jobs.py`) chains step 3 onto step 2 via a SLURM `--dependency`, so the whole submission
can be queued in one sitting with nobody watching for the reference jobs to finish:

```bash
jid_resnet=$(sbatch --parsable benchmarks/slurm/train_resnet50_cifar_diag.sh)
jid_vit=$(sbatch --parsable benchmarks/slurm/train_vit_small_cifar_diag.sh)
sbatch --dependency=afterok:$jid_resnet:$jid_vit benchmarks/slurm/dispatch_remaining_arms.sh
```

The dispatcher job waits (queued, no compute consumed) until both reference jobs complete with
exit code 0, reads their `total_s` back from `manifest.json` itself, and submits the remaining
jobs with the correct `WCT_BUDGET` (its `MODELS` array selects which model folders to dispatch). If either reference job fails, `afterok` is never satisfied and
the dispatcher sits as `DependencyNeverSatisfied` in `sq` — cancel it (`scancel`) and re-submit by
hand once the reference run is fixed, rather than leaving it queued indefinitely.

**4. Aggregate.** `--output-dir` is the *report* directory (`records.csv`, `epochs.csv`,
`summary.md`, `manifest.json`, up to 4 plots); each arm's own artefacts, the `--checkpoints` dumps
`ckpt_{0,0.01,0.1,0.5,1}.pt` included, go one level below it, under `<report dir>/<arm>/`.

- A **grouped** job points `--output-dir` at `outputs/<model>/`, so the combined seven-arm report
  sits there and the checkpoints under `outputs/<model>/<arm>/`.
- A **per-arm** job must point it at `outputs/<model>/<arm>/`, or six concurrent jobs would
  overwrite each other's `summary.md`; its checkpoints therefore land in the redundant-looking but
  correct `outputs/<model>/<arm>/<arm>/`. To compare arms across independent jobs, concatenate the
  per-arm CSVs. Re-running the entrypoint
locally with `--arms` listing several arms produces one combined report; across independent jobs,
concatenate the per-arm CSVs.

Track jobs with `sq`; do **not** poll it in a tight loop — the Alliance docs warn this degrades the
scheduler for everyone.

## What the scripts request, and why

- **`--gpus=h100_1g.10gb:1`** — a MIG slice (1/8 compute, 10 GB), not a full H100: `def-msh-ab`'s
  GPU allocation on Rorqual supports only that shape (confirmed there via `sshare -U` and a real
  validation run). `--gres=gpu:` is deprecated in favour of `--gpus`/`--gpus-per-node`. On an
  account with a full-GPU allocation, `--gpus=h100:1` (or `h100_3g.40gb:1`) is the one-line switch —
  and would let you drop `--fisher-batch-samples` and re-run the ResNet-50 arms without SUA.
- **`--mem=16G`** — CPU-side memory. `--mem=0` (all node memory) is actively harmful on a shared MIG
  node. The GPU-side budget is the 10 GB of the slice, which is what the calibration job measures.
- **`--cpus-per-task=8`**, matching `--num-workers 8` in each script, and under both clusters'
  documented per-GPU maximum (Fir 12, Rorqual 16). Raise both together if `sacct -j <id>
  --format=Elapsed,MaxRSS` suggests the job is data-loading bound.
- **`--time`, per model** — measured, from the calibration pass; the basis is quoted verbatim in
  every script's header and lives in `generate_jobs.py`'s `WALLTIME` table.

  | model | worst arm, ms/step | steps | training | `--time` (train / calibration) |
  |---|---:|---:|---:|---|
  | `mnist_autoencoder` | 6.91 (tekfac) | 2 200 | ~15 s | 00:20:00 / 00:20:00 |
  | `mlp_ln_mnist` | 2.02 (tekfac) | 8 580 | ~17 s | 00:20:00 / 00:20:00 |
  | `cnn_gn_cifar` | 3.89 (ekfac) | 10 530 | ~41 s | 00:20:00 / 00:20:00 |
  | `vit_micro_cifar` | 6.54 (tekfac) | 10 530 | ~69 s | 00:20:00 / 00:20:00 |
  | `cct_2_3x2_cifar` | 13.47 (ekfac) | 17 550 | ~4.1 min | 00:30:00 / 00:20:00 |
  | `resnet20_cifar` | 20.76 (tekfac) | 17 550 | ~6.3 min | 00:30:00 / 00:20:00 |
  | `vit_small_cifar` | 56.30 (ekfac) | 17 550 | ~17.1 min | 01:00:00 / 00:20:00 |
  | `resnet50_cifar` | 191.4 (ekfac) | 17 550 | ~58 min | 02:00:00 / 00:25:00 |

  Two facts bound the margin. Every calibration job completed inside its own `--time`, the
  smallest being 00:15:00 for 0.6 s of training, so module load + `virtualenv` + `pip install
  --no-index` + dataset load together take **under 15 minutes**. And under the WCT protocol every
  arm of one model shares the reference arm's budget, so one `--time` per model covers all seven —
  a *cheap* arm cannot overrun it, `--max-epoch-factor` only lets it fit more epochs into the same
  wall-clock. Each value is therefore ~15 min of setup headroom plus roughly twice the measured
  worst-arm training time.
- **No `--partition`** — deliberate; the Alliance docs' own guidance is to let the scheduler place
  the job from the requested resources.
- **`module purge` before `module load`** — the docs' own troubleshooting guidance, so jobs are
  submitted from a uniform environment.
- **`set -euo pipefail` and `cd "$SLURM_SUBMIT_DIR"`** — every path inside the scripts is relative to
  the repository root, so submit from there.

## What one job actually runs

```bash
python -m benchmarks.<model>.bench --arms <arm> --epochs <the model's own default> \
  [--budget-mode wct --wct-budget <T> --max-epoch-factor 3 | --budget-mode epochs] \
  --num-workers 8 --no-allow-download --data-root "$SLURM_SUBMIT_DIR/dataset" \
  --checkpoints 0,0.01,0.1,0.5,1 \
  --output-dir "$SLURM_SUBMIT_DIR/benchmarks/outputs/<model>/<arm>"
```

Everything else — learning rate, weight decay and its coupled/decoupled convention, damping,
`conv_sua`, `fisher_batch_samples` — is the `HParams` literal in that model's own `bench.py`,
which carries AdaFisher's own tuned values with their citations (`plan_lot8.md` §0.8,
`plan_exp_step1.md` D4). Override any
of them on the command line if you are running a variant; do not edit the defaults for one arm only.
