# SLURM jobs — one calibration job and seven optimizer arms per model

181 scripts: for each of the twenty model folders under `benchmarks/`, one calibration job, 7
per-arm training jobs (`diag, kfac, ekfac, tkfac, tekfac, adam, adamw`) and — for all but the two
ImageNet-224 models — one `train_<model>_all.sh` running all seven arms in a single job; plus two
campaign jobs (`train_v0_seeds.sh`, `sweep_mnist_autoencoder_lam.sh`). All generated by
`generate_jobs.py` — **edit that file, never the `.sh` files**. It enumerates the model folders
themselves (`plan_exp_step1.md` §6), reading each `Benchmark`'s own epoch count, arm list and
dataset, so a new model folder brings its own jobs with no edit here. Design rationale for every
choice below: `docs/reports/plan_lot8.md`, §0.7 (the WCT budget protocol), §0.11 (why the cluster
at all) and §1.5.

## Layout: one subdirectory per dataset

A model's jobs live beside its results, under the same one-level `output_group` its `bench.py`
declares:

| directory | models | results |
|---|---|---|
| `benchmarks/slurm/mnist/` | `mnist_autoencoder`, `mlp_ln_mnist` | `benchmarks/outputs/mnist/<model>/` |
| `benchmarks/slurm/cifar10/` | the 6 CIFAR-10 benches | `benchmarks/outputs/cifar10/<model>/` |
| `benchmarks/slurm/cifar100/` | the 6 CIFAR-100 benches | `benchmarks/outputs/cifar100/<model>/` |
| `benchmarks/slurm/imagenet/` | the 6 ImageNet-1K benches | `benchmarks/outputs/imagenet/<model>/` |

No model sits at the top level any more. Only three files do, and none of them belongs to one
dataset: `generate_jobs.py`, `train_v0_seeds.sh` (which spans MNIST *and* CIFAR-10, and writes to
`outputs/seeds/<model>/seed<n>/` — a layout of its own, deliberately left ungrouped because its
axis is the seed, not the dataset) and the hand-written `dispatch_remaining_arms.sh`, which reads
each model's group out of its own `bench.py`.

`fisher_ref/checkpoints.py` follows both layouts — `outputs/<group>/<model>/<arm>/` and the flat
`outputs/<model>/<arm>/` — so an old result tree keeps resolving and nothing had to move on the
same day the benches were grouped. It descends only into a directory named after a group some
bench actually declares, so `_calibration` and legacy trees such as `outputs/lot8_cifar10/` cannot
be mistaken for one.

`benchmarks/slurm/imagenet/` also holds one **hand-written** file among the generated ones,
`stage_imagenet.sh` — it builds the `ImageFolder` trees the ImageNet benches read. See
`imagenet/README.md`, which is the file to read before submitting anything there.

**Every `--time` in the flat and `cifar100/` directories is measured from a completed run**, not
extrapolated: each script's header quotes that model's reference-arm `total_s` on one
`h100_1g.10gb` slice, plus headroom (a CIFAR-100 row reuses its CIFAR-10 counterpart's
measurement — same 50 000 32x32 images, same split, an architecture differing only in head width,
and the header says so). **The `imagenet/` figures are ESTIMATED**, flagged as such in every
header: nothing there has run on this cluster yet, which is why each of those six models also has
a calibration job. Re-run `generate_jobs.py` after changing any model's epoch count or batch size.

**Cluster.** The Alliance Canada H100 clusters (Fir or Rorqual) that
`/Users/baolgr/Documents/AtlasAnalyticsLab` already runs on. Every cluster-specific line in these
scripts is copied from job scripts that have actually run there, not re-derived — that repository's
`experiments/default/slurm/README.md` documents each one against `docs.alliancecan.ca` and against
live `module spider` output, and is the file to read first if this is your first submission.

## Quickstart: from a pushed repo to running jobs

You've already pushed the repository to a remote reachable from the cluster (GitHub/GitLab, or a
bare repo of your own). This is what turns that push into running SLURM jobs, on a fresh account
that has never submitted here before.

1. **SSH into a login node** (Fir or Rorqual — pick the one your `def-msh-ab` allocation is on):

   ```bash
   ssh <username>@fir.alliancecan.ca      # or rorqual.alliancecan.ca
   ```

2. **Clone the repo onto the cluster's filesystem.** Pushing to a remote does not put files on the
   cluster by itself — clone from that same remote, into your project space (`~/projects/def-msh-ab/…`
   or `~/scratch/…`, not `$HOME`, which has a small quota):

   ```bash
   cd ~/projects/def-msh-ab/<username>
   git clone <your-remote-url> adafisher
   cd adafisher
   ```

   Already cloned from a previous attempt? `cd` into it and `git pull` instead.

3. **Stage the dataset into `dataset/`** — do this from your laptop, not the cluster: compute nodes
   on Rorqual have no internet, and the login node is not the place to run `torchvision`'s
   download.

   ```bash
   # locally, once: populate ./dataset/{cifar-10-batches-py,cifar-100-python,MNIST}/
   python -c "from torchvision.datasets import CIFAR10, CIFAR100, MNIST; [c('dataset', train=t, download=True) for c in (CIFAR10, CIFAR100, MNIST) for t in (True, False)]"
   rsync -av dataset/ <username>@fir.alliancecan.ca:~/projects/def-msh-ab/<username>/adafisher/dataset/
   ```

   ImageNet-1K is not staged this way and cannot be downloaded by `torchvision` at all — see
   `imagenet/README.md`.

   Use the login node for `rsync` (or a dedicated data-transfer node if your cluster has one) —
   never a Globus-only endpoint.

4. **Confirm `benchmarks/slurm/logs/` exists** (it should — tracked via `logs/.gitkeep`):

   ```bash
   ls benchmarks/slurm/logs/
   ```

5. **Nothing to install by hand.** Each job builds its own `$SLURM_TMPDIR` virtualenv from
   `requirements-cluster.txt` and loads its modules (`StdEnv/2023 gcc/13.3 cuda/12.6 python/3.11.5`)
   at submission time — do not `pip install` anything on the login node.

6. **Submit, in the order below** ("Submission order"). Start with the calibration job of the
   model you want; do not fire all 73 scripts at once.

Everything from here on assumes you are in the repository root on the login node, submitting with
`sbatch benchmarks/slurm/<script>.sh`.

## Before your first submission

1. **Get the repository onto the cluster** (`git push`/`clone`, or `rsync -av --exclude-from=.gitignore .`).
2. **Stage CIFAR-10 into `dataset/`** — required. Rorqual's compute nodes have **no internet**, and
   every script passes `--no-allow-download` so a missing dataset fails immediately with a clear
   error instead of hanging on a network timeout:
   ```bash
   # locally, once: populate ./dataset/cifar-10-batches-py/
   python -c "from torchvision.datasets import CIFAR10; CIFAR10('dataset', train=True, download=True); CIFAR10('dataset', train=False, download=True)"
   rsync -av dataset/ your-cluster:~/path/to/adafisher/dataset/
   ```
   Use the login/copy node for `rsync`, not a Globus-only endpoint.
3. `benchmarks/slurm/logs/` must already exist (`--output` writes there) — it is kept in the
   repository by `logs/.gitkeep`.
4. Nothing else: each job builds its own `$SLURM_TMPDIR` virtualenv from `requirements-cluster.txt`
   and sets `PYTHONPATH=$SLURM_SUBMIT_DIR/src`. The package is deliberately not installed (see that
   file's header).

## Submission order

MNIST and CIFAR-10 must already be staged under `dataset/` (Quickstart step 3), and MNIST is
needed for `mnist_autoencoder`, `mlp_ln_mnist` and the sweep.

**1. Calibration first, for any model whose `--time` you do not trust.** Every value in the
`--time` table below is already measured from a completed run, so this is optional on a
re-submission of the same model at the same epoch count and batch size. It *is* required after
changing either, or on a different GPU shape.

```bash
sbatch benchmarks/slurm/calibrate_resnet50_cifar.sh    # ~2 min, prints per-arm step time + VRAM
```

**2. Training, one grouped job per model.** No ordering constraint between models and nothing to
chain — each job runs its own reference arm first and derives its own budget. Submit the two long
ones first so they start queueing while the short ones churn:

```bash
sbatch benchmarks/slurm/train_resnet50_cifar_all.sh     # 07:00:00, the campaign's long pole
sbatch benchmarks/slurm/train_vit_small_cifar_all.sh    # 02:45:00
for m in resnet20_cifar cct_2_3x2_cifar vit_micro_cifar cnn_gn_cifar \
         mlp_ln_mnist mnist_autoencoder; do
  sbatch benchmarks/slurm/train_${m}_all.sh
done
```

**3. Extra seeds for the Fisher-drift campaign.** `plan_exp_draft_v0.md` §3.4 wants 3 training
seeds per model, 5 in regime A; seed 0 exists for all five of its models, so this job runs the
remaining 16 (model, seed) pairs. It samples only the two trajectories §3.5 uses — AdamW and
AdaFisher — so it is `2 x T_diag` per pair, ~1 h total. Independent of everything above; writes to
`outputs/seeds/<model>/seed<n>/` and never touches `outputs/<group>/<model>/`.

```bash
sbatch benchmarks/slurm/train_v0_seeds.sh               # 01:45:00
```

This is the best information-per-GPU-hour job of the campaign: ~1 h, against 8 h for the two large
models, which answer the lot-8 convergence question rather than the drift one. Note it deliberately
carries **no** `--lr-schedule` flag — seed 0 ran under the default `nominal` schedule and these
seeds must match it to be comparable with it.

**4. Sweeps, any time.** Independent of everything above; writes to `outputs/sweeps/`, never to a
model's own directory.

```bash
sbatch benchmarks/slurm/sweep_mnist_autoencoder_lam.sh  # 00:20:00
```

`lam` has already been swept (locally, `{1e-5, 1e-3, 1e-1}`) and the answer is settled — it moves
the four Kronecker modes by under 1% — so this one is not worth a job unless you want it confirmed
on an H100.

**5. Watch, then pull.**

```bash
squeue -u "$USER" -o "%.10i %.28j %.2t %.10M %.10l %R"
sacct -u "$USER" -X --format=JobID,JobName%28,State,Elapsed,ExitCode   # after they finish
# from your laptop — reports and plots only, not the multi-GB checkpoints:
rsync -av --include='*/' --include='*.csv' --include='*.md' --include='*.json' \
      --include='*.png' --exclude='*' \
      <username>@fir.alliancecan.ca:~/projects/def-msh-ab/<username>/adafisher/benchmarks/outputs/ \
      benchmarks/outputs/
```

Pull the checkpoints separately, and only for the models whose `theta` trajectories you actually
need — `resnet50_cifar` alone is 2.7 GB of them.

## Which submission strategy

Two ways to run one model's seven arms; the trade is parallelism against setup cost.

| | jobs per model | when |
|---|---|---|
| `train_<model>_all.sh` | **1** | **default, all eight models** |
| `train_<model>_<arm>.sh` + dispatcher | 7 (+1) | only if you need the arms to run concurrently |

**Grouping is now the default for every model, including the two large ones.** Two things changed
since this file said otherwise:

- `main` used to write its report only after the last arm, so a crash in a later arm lost every
  arm that had completed — it cost `resnet20_cifar_all` and `mlp_ln_mnist_all` two finished arms
  each (cause in `_eigh_utils.py`'s docstring). **`main` now rewrites the whole report after every
  completed arm**, so a grouped job loses at most the arm it died in.
- The per-arm strategy requires copying the reference arm's measured `total_s` into six
  `--wct-budget` flags by hand. That is how the first campaign produced a result set whose
  checkpoint fractions were silently wrong on 6 of 7 arms
  (`benchmarks/archives/2026-09-10_prefix_campaign/README.md`). A grouped job derives the budget
  in-process: nothing to copy, nothing to get wrong.

What grouping does *not* buy is machine time: setup is measured at ~40 s, so the six saved setups
are ~4 min per model. What it costs is backfill latency — `resnet50_cifar_all` is a 7 h job where
seven concurrent 50 min jobs would start sooner. That is the only reason to still prefer the split
strategy, and the per-arm scripts remain generated for it.

Whole campaign, grouped: **9 jobs** (8 models + 1 sweep), **~11 h of MIG-slice time**, of which
`resnet50_cifar` alone is 5.5 h.

```bash
# every model, one job each — nothing to chain, no WCT_BUDGET to pass
for m in mnist_autoencoder mlp_ln_mnist cnn_gn_cifar vit_micro_cifar \
         cct_2_3x2_cifar resnet20_cifar vit_small_cifar resnet50_cifar; do
  sbatch benchmarks/slurm/train_${m}_all.sh
done
```

If you do want the two large models split instead, the reference arm must run first and its
measured time be passed to the other six:

```bash
MODELS="resnet50_cifar vit_small_cifar"
DEPS=""
for m in $MODELS; do
  jid=$(sbatch --parsable benchmarks/slurm/train_${m}_diag.sh); DEPS="$DEPS:$jid"
done
sbatch --dependency=afterok${DEPS} --export=ALL,MODELS="$MODELS" \
       benchmarks/slurm/dispatch_remaining_arms.sh
```

The per-arm steps below apply to the split strategy.

## The LR schedule (`--lr-schedule budget`)

Every generated *budgeted* job passes `--lr-schedule budget`, which is a **protocol change** from
the first campaign, not a tuning knob. Under a shared `T_max = --epochs` the arms of one model
complete different epoch counts inside one wall-clock budget, and both ends were biased:

- a cheap arm overshoots the nominal count, and `torch`'s `CosineAnnealingLR` is *periodic*, so its
  LR climbs back towards `base_lr`. Every overshooting arm was `adam`/`adamw` (7 of 8 models);
  `resnet20_cifar/adam` reached `lr = 0` at epoch 49, trained 9 more epochs with the LR rising back
  to `6.2e-5`, and its best val acc decayed from 88.82% to 88.06%;
- an expensive arm stops short of the floor. `resnet50_cifar/ekfac` stopped at epoch 38 of 50 with
  `lr` still at `1.6e-4`; across the five Fisher arms `corr(epochs completed, best val acc)` was
  **+0.98 / +0.92 / +0.92** on the three long models, i.e. the ranking of the modes was largely a
  ranking of how far each got through the shared schedule.

`--lr-schedule budget` anneals each budgeted arm over **its own budget**, so every arm completes
one full cosine. The reference arm is unbudgeted by construction — it *defines* the budget — and
always keeps the nominal schedule. Derivation and the clamped-nominal fallback:
`benchmarks/common/schedules.py`; assertions: `tests/test_lr_schedule.py`.

One cost, worth knowing: a budgeted arm's LR now depends on measured elapsed time, so two runs of
it agree statistically, not bit-for-bit. `--lr-schedule nominal` keeps the old, fully deterministic
behaviour (now clamped, so the LR never rises).

**1. Calibrate first (2 jobs, ~45 min + ~30 min).**

```bash
sbatch benchmarks/slurm/calibrate_resnet50_cifar.sh
sbatch benchmarks/slurm/calibrate_vit_small_cifar.sh
```

2 epochs of every arm on a 5 000-example training subset. What to read off its `summary.md` and its
log, before spending real cluster time:

- **median step time and steps/s per arm** → turns each training script's `--time` from an
  extrapolation into a measurement (see "What the scripts request" below);
- **peak VRAM** → the `peak VRAM` column of `summary.md` (`torch.cuda.max_memory_allocated`,
  reset per arm, covering training *and* evaluation) confirms `plan_lot8.md` §0.4's
  `fisher_batch_samples=32` (ResNet-50) and §0.5's mandatory `conv_sua=True` keep `ekfac`/`tekfac`
  inside the 10 GB MIG slice. It is *allocator* memory: the CUDA context and cuDNN workspaces sit
  on top, so it under-reports `nvidia-smi` by roughly 0.5-1 GB. If they do not, lower
  `--fisher-batch-samples` (16, 8) rather than dropping an arm; if there is headroom to spare, raise
  it — the knob changes the curvature *estimator*, so it is reported in the summary and must not be
  changed silently between arms.

**2. The two reference arms (2 jobs).** Their measured wall-clock time is every other arm's budget
(`plan_lot8.md` §0.7 — AdaFisher's own WCT protocol, `adafisher_2405.16397.pdf` §5).

```bash
sbatch benchmarks/slurm/train_resnet50_cifar_diag.sh
sbatch benchmarks/slurm/train_vit_small_cifar_diag.sh
```

Read the budget back once they finish:

```bash
python -c "import json;print(json.load(open('benchmarks/outputs/cifar10/resnet50_cifar/diag/manifest.json'))['arms']['diag']['total_s'])"
```

**3. The remaining 6 arms per model**, each with that number:

```bash
for arm in kfac ekfac tkfac tekfac adam adamw; do
  sbatch --export=ALL,WCT_BUDGET=<resnet50_cifar diag total_s> benchmarks/slurm/train_resnet50_cifar_$arm.sh
  sbatch --export=ALL,WCT_BUDGET=<vit_small_cifar diag total_s> benchmarks/slurm/train_vit_small_cifar_$arm.sh
done
```

All 12 are independent and can run concurrently. **Without `WCT_BUDGET` a job still runs**, falling
back to `--budget-mode epochs` — the equal-epoch comparison `plan.md` §6.3 explicitly calls rigged
in favour of the expensive modes. Usable as a cross-check, not as this lot's headline result.

**Unattended alternative.** `dispatch_remaining_arms.sh` (hand-maintained, not generated by
`generate_jobs.py`) chains step 3 onto step 2 via a SLURM `--dependency`, so the whole submission
can be queued in one sitting with nobody watching for the reference jobs to finish:

```bash
jid_resnet=$(sbatch --parsable benchmarks/slurm/train_resnet50_cifar_diag.sh)
jid_vit=$(sbatch --parsable benchmarks/slurm/train_vit_small_cifar_diag.sh)
sbatch --dependency=afterok:$jid_resnet:$jid_vit benchmarks/slurm/dispatch_remaining_arms.sh
```

The dispatcher job waits (queued, no compute consumed) until both reference jobs complete with
exit code 0, reads their `total_s` back from `manifest.json` itself, and submits the remaining
jobs with the correct `WCT_BUDGET` (its `MODELS` array selects which model folders to dispatch). If either reference job fails, `afterok` is never satisfied and
the dispatcher sits as `DependencyNeverSatisfied` in `sq` — cancel it (`scancel`) and re-submit by
hand once the reference run is fixed, rather than leaving it queued indefinitely.

**4. Aggregate.** `--output-dir` is the *report* directory (`records.csv`, `epochs.csv`,
`summary.md`, `manifest.json`, up to 4 plots); each arm's own artefacts, the `--checkpoints` dumps
`ckpt_{0,0.01,0.1,0.5,1}.pt` included, go one level below it, under `<report dir>/<arm>/`.

- A **grouped** job points `--output-dir` at `outputs/<group>/<model>/`, so the combined seven-arm
  report sits there and the checkpoints under `outputs/<group>/<model>/<arm>/`.
- A **per-arm** job must point it at `outputs/<group>/<model>/<arm>/`, or six concurrent jobs would
  overwrite each other's `summary.md`; its checkpoints therefore land in the redundant-looking but
  correct `outputs/<group>/<model>/<arm>/<arm>/`. To compare arms across independent jobs, concatenate the
  per-arm CSVs. Re-running the entrypoint
locally with `--arms` listing several arms produces one combined report; across independent jobs,
concatenate the per-arm CSVs.

Track jobs with `sq`; do **not** poll it in a tight loop — the Alliance docs warn this degrades the
scheduler for everyone.

## What the scripts request, and why

- **`--gpus=h100_1g.10gb:1`** — a MIG slice (1/8 compute, 10 GB), not a full H100: `def-msh-ab`'s
  GPU allocation on Rorqual supports only that shape (confirmed there via `sshare -U` and a real
  validation run). `--gres=gpu:` is deprecated in favour of `--gpus`/`--gpus-per-node`. On an
  account with a full-GPU allocation, `--gpus=h100:1` (or `h100_3g.40gb:1`) is the one-line switch —
  and would let you drop `--fisher-batch-samples` and re-run the ResNet-50 arms without SUA.
- **`--mem=16G`** — CPU-side memory. `--mem=0` (all node memory) is actively harmful on a shared MIG
  node. The GPU-side budget is the 10 GB of the slice, which is what the calibration job measures.
- **`--cpus-per-task=8`**, matching `--num-workers 8` in each script, and under both clusters'
  documented per-GPU maximum (Fir 12, Rorqual 16). Raise both together if `sacct -j <id>
  --format=Elapsed,MaxRSS` suggests the job is data-loading bound.
- **`--time`, per model** — measured from completed runs; the basis is quoted verbatim in every
  script's header and lives in `generate_jobs.py`'s `WALLTIME` / `GROUPED` tables.

  | model | `T_diag` (per arm) | grouped job | per-arm job | calibration |
  |---|---:|---|---|---|
  | `mnist_autoencoder` | 13.7 s | 00:15:00 | 00:15:00 | 00:10:00 |
  | `mlp_ln_mnist` | 21.6 s | 00:15:00 | 00:15:00 | 00:10:00 |
  | `cnn_gn_cifar` | 46.0 s | 00:20:00 | 00:20:00 | 00:10:00 |
  | `vit_micro_cifar` | 67.4 s | 00:25:00 | 00:25:00 | 00:10:00 |
  | `cct_2_3x2_cifar` | 237.5 s | 00:45:00 | 00:45:00 | 00:10:00 |
  | `resnet20_cifar` | 360.3 s | 01:05:00 | 01:05:00 | 00:10:00 |
  | `resnet50_cifar` | 2822.8 s | 07:00:00 | 01:15:00 | 00:15:00 |
  | `vit_small_cifar` | 987.8 s | 02:45:00 | 00:30:00 | 00:10:00 |

  | job hors-modèle | contenu | `--time` |
  |---|---|---|
  | `train_v0_seeds` | 16 paires (modèle, graine), 2 bras | 01:45:00 |
  | `sweep_mnist_autoencoder_lam` | `lam ∈ {1e-5, 1e-3, 1e-1}`, 7 bras | 00:20:00 |

  Three measurements bound the margin. **Setup is ~40 s**, not the ~10 min an earlier version of
  this file assumed: `cal_mlp_ln_mnist` COMPLETED in `00:00:44` *including* module load,
  `virtualenv`, `pip install --no-index` and 7 arms × 2 epochs — the wheelhouse is node-local, so
  the install is a disk copy, not a download. **Validation adds ~6%** on top of training
  (`cct_2_3x2_cifar_all` ran `00:30:22` against 1662.5 s of accounted training; eval time is
  excluded from the budget clock but not from the job's wall-clock). And under the WCT protocol
  **every arm of a model takes the reference arm's time**, so one `--time` per model covers all
  seven — `--max-epoch-factor` only lets a cheap arm fit more epochs into the same wall-clock,
  never overrun it.

- **No `--partition`** — deliberate; the Alliance docs' own guidance is to let the scheduler place
  the job from the requested resources.
- **`module purge` before `module load`** — the docs' own troubleshooting guidance, so jobs are
  submitted from a uniform environment.
- **`set -euo pipefail` and `cd "$SLURM_SUBMIT_DIR"`** — every path inside the scripts is relative to
  the repository root, so submit from there.

## What one job actually runs

```bash
python -m benchmarks.<model>.bench --arms <arm> --epochs <the model's own default> \
  [--budget-mode wct --wct-budget <T> --max-epoch-factor 3 | --budget-mode epochs] \
  --num-workers 8 --no-allow-download --data-root "$SLURM_SUBMIT_DIR/dataset" \
  --checkpoints 0,0.01,0.1,0.5,1 \
  --output-dir "$SLURM_SUBMIT_DIR/benchmarks/outputs/<group>/<model>/<arm>"
```

Everything else — learning rate, weight decay and its coupled/decoupled convention, damping,
`conv_sua`, `fisher_batch_samples` — is the `HParams` literal in that model's own `bench.py`,
which carries AdaFisher's own tuned values with their citations (`plan_lot8.md` §0.8,
`plan_exp_step1.md` D4). Override any
of them on the command line if you are running a variant; do not edit the defaults for one arm only.
